# 01 — 선택한 맛집들의 왕복 최적 경로 추천

## Outcome

사용자가 이동시간순 리스트에서 방문하고 싶은 곳을 최대 4곳까지 선택하면, 출발점에서 시작해 선택한 곳들을 모두 들렀다가 출발점으로 돌아오는 방문 순서 중 총 이동시간이 가장 짧은 순서가 방문 순서·구간별 이동시간·왕복 전체 이동시간과 함께 나타난다.

## Blockers

None. (선행 스펙 [travel-time-ranked-restaurant-list](../../travel-time-ranked-restaurant-list/spec.md)의 태스크 01이 이미 completed 상태이며, 이 태스크는 그 화면 위에 이어서 구현한다.)

## Acceptance criteria

- [x] 이동시간순 리스트의 각 항목을 선택할 수 있고, 4곳이 선택된 상태에서는 추가 선택이 막힌다는 것을 사용자가 알 수 있다.
- [x] 아무것도 선택하지 않은 상태에서는 방문 순서 추천 결과가 나타나지 않는다.
- [x] 1곳 이상 선택하면 방문 순서 추천을 받을 수 있다.
- [x] 추천된 방문 순서는 출발점에서 시작해 선택한 곳을 모두 거쳐 출발점으로 돌아오는 구조다.
- [x] 선택한 곳이 2곳 이상일 때, 추천된 순서는 가능한 다른 방문 순서들과 비교했을 때 총 이동시간이 가장 짧다.
- [x] 결과 화면에는 방문 순서, 각 구간의 이동시간, 왕복 전체 이동시간이 모두 표시된다.
- [x] 선택을 추가하거나 해제하면 방문 순서와 이동시간이 그 변경을 반영해 다시 계산된다.
- [x] 이동수단은 이전 화면에서 고른 도보/자동차 설정을 그대로 따르고, 이 화면에서 다시 고르지 않는다.

## Constraints

None.

## Verification

- 서로 다른 대륙의 도시(예: 서울, 파리)에서 3~4곳을 선택해 실제로 방문 순서와 각 구간·총 이동시간을 확인하고, 총 이동시간이 그럴듯한 범위인지, 더 짧아 보이는 다른 순서가 없는지 눈으로 확인한다.
- 1곳만 선택했을 때와 4곳을 선택했을 때 각각 정상 동작하는지 확인한다.
- 4곳 선택 후 추가 선택을 시도했을 때 막히는 것을 확인한다.
- 선택을 추가/해제했을 때 결과가 다시 계산되는 것을 확인한다.
- `npm run typecheck`, `npm run lint`, `npm run test`가 통과한다.
